A decentralized exchange on BSV

A decentralized exchange made of independent instances, not one server.

The Open Exchange swaps BSV and 1Color tokens directly against pools that live on the BSV chain. Your wallet keeps custody. Each enabled token is served by its own instance, with its own validator and public lookup. Validators compete on terms.

Step 1 of 7

Custody stays with you

Your wallet holds the sats and tokens. Nothing is deposited to the exchange, so there is no exchange balance to withdraw.

Instances, not accounts

The Open Exchange is not one exchange server with a list of user accounts. When a token is enabled, the host creates an instance for that token. The instance has its own address and identity, and it serves that token's traffic: the overlay topic that accepts its transactions, the lookup that lists its pools and prices, and the validator and relay that sign and carry swaps.

One token, one instance

An enabled token gets its own instance at its own address. The instance is that token's exchange surface, not a row in a global book.

Public lookups

The instance publishes live pools, reserves and prices. Anyone can read the lookup and the public read API without an account.

Discovery is optional

A separate discovery instance advertises token deploys. It can be switched off; a swap against a known token does not depend on it.

Stopping is not deleting

An instance can be stopped and started. The pools stay on the chain; stopping only takes the service off the network.

Validators, relays and fees

A pool is one token/BSV pair, affirmed by a validator when it is deployed. The validator's signature is written into the pool output itself, so the pool attests itself. The lookup lists only pools whose affirmation verifies.

When a taker swaps, the validator checks the pool's state, its own fee terms and the transaction, then signs the pool input. The taker signs the rest; the validator signs last. Fees are the validator's runtime terms, set by the exchange admin — not baked into the software.

LP fee

Paid to the pool's LP key, in the asset being swapped in.

Validator fee

Paid to the validator that signs the swap, in the input asset.

Relay commission

Paid to the relay that carried the swap, in the input asset.

The market side is the relay: it carries the transaction to the validator the taker names and takes a commission. Its minimum commission is a listing preference on the Swap page, not an enforcement rule: a swap can still go directly to a validator.

A validator can refuse to sign or go offline. It cannot move the pool's funds outside the contract, and the LP can close the pool at any time.

Who controls what

Control is split. The host runs the machinery, the admin configures tokens, the LP owns the pool, and the validator can only sign or refuse.

What “decentralized” means here — and what it does not

It does mean

  • No custodian: funds stay in wallets and pools.
  • No central matching engine: pools are chain outputs and swaps are transactions.
  • No single service: each token has its own instance, and validators can be independent.
  • Public verification: lookups and read APIs let anyone check state without an account.
  • Permissionless hosting: anyone can run a host and serve a token.

It does not mean

  • It is not a separate consensus network. BSV is the settlement layer and final arbiter.
  • A hosted exchange is one machine with one operator key. Decentralization comes from being able to run your own, not from every host being trustless.
  • Governance is a claim, not a vote: the first wallet to claim a hosted exchange becomes admin while the host keeps root.
  • You still rely on validators to be live and to sign correctly. You do not rely on them to hold your funds.
